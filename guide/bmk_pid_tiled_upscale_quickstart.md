# BMK PiD Tiled Upscale — 빠른 시작 (v2.3)

그림을 가로세로 4배로 키우는 노드입니다. 큰 그림도 메모리 걱정 없이 처리하려고
이미지를 조각으로 나눠 한 조각씩 키운 뒤 다시 이어 붙입니다.

이 문서는 **처음 쓰는 사람이 배선하고 값을 정하는 데 필요한 것만** 담았습니다.
실측 데이터와 설계 근거는 [핵심 가이드](bmk_pid_tiled_upscale_guide.md)에 있습니다.

---

## 왜 조각으로 나눠서 처리하나

이 노드가 쓰는 **PiD** 는 업스케일 전용으로 만들어진 AI 모델입니다. 성질이 세 가지
있고, 노드 설계가 전부 여기서 나옵니다.

- **배율은 4배 고정입니다.** 2배나 3배를 고를 수 없습니다. 2배가 목표여도 4배로
  키운 뒤 뒤에서 줄여야 합니다.
- **한 번에 그릴 수 있는 크기가 정해져 있습니다.** 1024×1024 를 받아 4096×4096 을
  내놓도록 학습됐습니다.
- **그 크기를 넘으면 색이 무너집니다.** 형태는 멀쩡한데 밝은 부분이 분홍빛으로
  물들고 하늘이 청록으로 뜹니다.

그래서 노드는 원본을 **조각(타일)** 으로 나눕니다. 조각 하나가 모델이 감당할 수 있는
크기 안에 들어가도록 격자를 자동으로 계산하고, 조각마다 4배로 키운 다음 서로 겹치는
부분을 부드럽게 섞어 한 장으로 되돌립니다.

```
1. 원본을 격자로 나눔      2. 조각마다 여유분 붙여 생성     3. 가운데만 이어 붙임
   ┌─────┬─────┐             ┌───────────────┐               ┌─────┬─────┐
   │     │     │             │░░░░░░░░░░░░░░░│               │     ┊     │
   ├─────┼─────┤             │░░┌─────────┐░░│               ├┈┈┈┈┈┼┈┈┈┈┈┤
   │     │     │             │░░│  core   │░░│               │     ┊     │
   └─────┴─────┘             │░░└─────────┘░░│               └─────┴─────┘
                             │░░░░░░░░░░░░░░░│
                             └───────────────┘
                              ░ = context_pixel                ┊ = core_overlap
                              생성에만 쓰고 버림                 서서히 섞어 이음새 제거
```

## 최소 배선

```
이미지 불러오기 ─┬─────────────────────────────────────────┐
                 │                                         │
BMK PiD Loader ──┼─→ BMK PiD Tiled Upscale ─→ BMK Wavelet Tone Restore
                 │      (여기서 4배)                │  ↑ reference
                 └──────────────────────────────────┼──┘
                                                    ↓
                                          BMK Scale To Target ─→ 저장
                                            ↑ source_image
                                            └── 원본
```

**원본 이미지를 세 군데에 연결합니다** — 업스케일 노드의 `image`, Wavelet Tone
Restore 의 `reference`, Scale To Target 의 `source_image`. 뒤의 두 노드는 "원본이
이랬으니 여기에 맞춰라"라는 기준으로 원본을 씁니다.

**Wavelet Tone Restore 는 빼지 마세요.** 업스케일 노드가 만든 색 오차의 약 75% 를
이 노드가 걷어냅니다. 없으면 색이 눈에 띄게 나빠집니다.

필름 그레인 같은 질감을 넣는다면 **반드시 맨 마지막, 최종 저장 해상도에서** 넣으세요.
그레인 뒤에 크기 조절이 오면 입자가 평균 내어져 사라집니다.

## 파라미터 — 손대는 빈도 순

위젯이 많아 보이지만 실제로 만질 일이 있는 건 서너 개뿐입니다. 아래는 위젯 나열
순서가 아니라 **얼마나 자주 건드리는지** 순으로 묶었습니다.

### 고정 — 바꾸면 안 되거나, 바꿀 이유가 없는 것

특히 위의 두 개는 틀리면 **에러 없이 결과만 조용히 망가집니다.**

| 파라미터 | 값 | 무슨 뜻인가 |
|---|---|---|
| `pid_vae` ⚠ | `pixel_space` | PiD 전용 디코더. 다른 걸 고르면 로더가 바로 막습니다 |
| `latent_format` ⚠ | 인코딩 VAE 계열 | **그림을 만든 모델이 아니라, 그림을 AI 형태로 변환할 때 쓴 VAE 를 따릅니다.** Qwen VAE 로 변환했으면 `qwenimage` |
| `pid_input_size` | `1024` | 조각 하나의 최대 크기. 모델이 학습한 크기라 올리면 색이 무너집니다 |
| `tile_shape` | `auto` | 격자 자동 계산. `square` 는 옛 방식 비교용 |
| `color_match` | `mean_std` | 조각별 색 보정. `mean` 은 실측상 `off` 와 거의 같아 사실상 꺼진 것입니다 |
| `padding_fill` | `reflect` | 이미지 바깥을 채우는 방식 |
| `fuse_method` | `pyramid` | 조각을 섞는 가중치 방식 |
| `steps` | `4` | 4스텝 전용 모델입니다 |
| `accum_dtype` | `fp32` | RAM 이 빠듯할 때만 `fp16` |

### 기본값 — 먼저 그대로 돌려 보고, 결과를 보고 조정

| 파라미터 | 기본 | 무슨 뜻이고, 언제 조정하나 |
|---|---|---|
| `context_pixel` | `128` | 조각 가장자리 여유분. 생성에만 쓰고 버립니다. **느리면 0 으로** — 조각 수가 가장 크게 줄어듭니다 |
| `core_overlap` | `64` | 조각끼리 겹치는 폭. **이음새가 보이면 128 로** |
| `degrade_sigma` | `0.06` | 원본에 얼마나 충실할지. 낮을수록 충실하고 색이 덜 튑니다. 디테일이 아쉬우면 0.10 까지 |
| `tile_tolerance` | `1.3` | 조각을 얼마나 크게 가져갈지의 여유. 내리면 더 잘게 쪼갭니다 |
| `model_shift` | `0.0` | 과하게 날카롭거나 경계에 흰 테가 보일 때 2~8 로. **색 문제에는 효과가 없습니다** |
| `color_match_strength` | `1.00` | 위 색 보정의 세기 |
| `seed_mode` | `same` | 모든 조각에 같은 씨앗값. 조각별로 질감이 달라지는 걸 막습니다 |

### 메모리 — 느리거나 메모리가 부족할 때

조각을 다시 가로로 잘라 나눠 그리는 기능입니다. 켜 두는 것이 기본입니다.

| 파라미터 | 기본 | 설명 |
|---|---|---|
| `context_windows` | `on` | 끄면 조각 하나를 통째로 그립니다. 메모리를 훨씬 많이 씁니다 |
| `context_length` | `2048` | 한 번에 그리는 세로 높이. 메모리가 부족하면 내립니다 |
| `context_overlap` | `512` | 위 구간끼리 겹치는 폭. `context_length` 의 1/4 정도로 함께 조절 |

> **결과를 비교할 때** — 한 장만 보고 판단하지 마세요. 씨앗값(seed)만 바꿔도 생기는
> 차이가 설정을 바꿔 생기는 차이만큼 큽니다. **최소 3개 씨앗**으로 세트를 만들어
> 보세요. 한 장씩 비교하면 계속 운에 속습니다.

## 증상 → 처방

| 증상 | 원인과 처방 |
|---|---|
| 결과 색이 원본과 완전히 딴판 | `latent_format` 이 실제 인코딩에 쓴 VAE 와 다릅니다. 콘솔 로그를 확인하세요. **가장 흔한 실수** |
| 밝은 부분이 분홍빛, 하늘이 청록빛 | 조각이 모델의 학습 크기를 넘었습니다. v2.3 의 `auto` 모드에서는 구조적으로 생기지 않습니다. 나온다면 `pid_input_size` 를 1024 위로 올렸거나 `square` 모드를 쓰는 중입니다 |
| 조각 경계선이 보임 | `core_overlap` 을 64 → 128 로 |
| 너무 느림 / 조각이 너무 많음 | `context_pixel` 을 0 으로 내리세요 |
| 메모리 부족(OOM) | `context_windows` 를 켜고 `context_length` 를 내리세요. 노드가 한 번은 자동 재시도합니다 |
| 선이 튀고 경계에 흰 테 | `model_shift` 를 2~8 로. 디테일이 조금 줄어듭니다 |
| 전체 톤이 밍밍함 | 업스케일 노드가 아니라 Wavelet Tone Restore 의 `levels` 를 조절하세요 |
| `타일 격자를 찾지 못했습니다` 에러 | `context_pixel` 이 `pid_input_size` 의 절반 이상입니다. 줄이세요 |

## 한 번씩은 겪는 것들

- **VAE 가 두 개 등장합니다.** `pid_vae` 는 결과를 그림으로 되돌리는 용도로
  `pixel_space` 고정이고, `encode_vae` 는 원본을 AI 형태로 변환하는 용도로 그림을
  만든 모델과 같은 계열입니다. 서로 다른 물건입니다.
- **2배가 목표여도 4배 비용이 듭니다.** 모델이 4배 고정이라 줄이는 건 뒤에서 합니다.
- **기존 워크플로우를 v2.3 으로 올렸다면** `color_match` 값을 확인하세요. 저장된 값이
  그대로 유지되므로, `mean` 이었다면 색 보정이 꺼진 상태로 계속 돌아갑니다.
  `mean_std` 로 바꾸세요.
- **큰 원본일수록 조각이 빠르게 늘어납니다.** 모델이 1024 크기로만 학습된 데서 오는
  제약이라 우회로가 없습니다.
